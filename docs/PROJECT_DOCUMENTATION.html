1 How the Code Works

1. Client Request
React (localhost:5173) sends HTTP requests via Axios to Laravel (127.0.0.1:8000/api).
2. Middleware Timer
ApiLoggerMiddleware::handle() records the start time and passes the request to the controller.
3. Instant Response
Controller queries local pgsql (students/notes) and sends the response immediately.
4. Async Queueing
terminate() runs after response is sent and pushes StoreApiLogJob to the api-logs queue.
5. Batch Insert → Neon
logs:process-batches pops 100 jobs and bulk-inserts them into Neon Primary (log_pgsql).
6. Replica Reads
GET /api/logs reads from Neon Read Replica(s) with sticky => false.

2 Completed Requirements & How They Were Built

1. Dedicated PostgreSQL Instance
DONE

Isolated API log storage from app data so logging traffic never competes with user/note queries.

  • Configured log_pgsql in backend/config/database.php & backend/.env pointing to Neon (api-logs-db, SSL required).
  • Added $withinTransaction = false to log migrations for Neon's PgBouncer pooler.
2. High-Volume Simulation (4,000+/min)
DONE

Avoided per-request DB round-trips by queuing and batch-inserting logs.

  • Updated ApiLoggerMiddleware to dispatch StoreApiLogJob to queue api-logs.
  • Built logs:process-batches (100-row bulk insert) & logs:simulate.
  • Benchmarked 4,269 logs in 44.02s (5,819 inserts/min).
3. Load Balancing & High Availability
DONE

Separated read and write traffic and leveraged Neon's multi-AZ architecture.

  • HA: Neon multi-AZ Safekeepers/Pageservers + built-in PgBouncer (-pooler).
  • LB: Laravel read/write split via LOG_DB_WRITE_HOST & LOG_DB_READ_HOSTS.
  • Verified with pg_is_in_recovery(): true on read, false on write.
4. Partitioning & Parquet Archival
DONE

Replaced slow row-by-row CSV archival with date partitions and compressed Parquet.

  • Converted api_logs to PARTITION BY RANGE (created_at) (2026_11, 2026_12, 2027_01, default).
  • Updated logs:archive to export zstd-compressed .parquet via export_to_parquet.py & log SHA-256 checksums in api_log_archives.
5. Optimized Indexing Strategy
DONE

Added two targeted indexes matching ApiLogController::index() without hurting insert speed.

  • BRIN index on created_at (tiny footprint for time-series appends).
  • Composite B-tree on (method, status_code, created_at DESC).
  • EXPLAIN ANALYZE improved 10.284 ms → 1.668 ms.
6. Deployment & Ops Documentation
DONE

Prepared full operational runbooks and architecture docs for the team.

  • Created docs/POSTGRESQL_OPERATIONS.md (setup, monitoring SQL, pg_dump/pg_restore, troubleshooting).
  • Created this visual summary (docs/PROJECT_DOCUMENTATION.html).

4 Quick Run Commands

# 1. Run Neon log migrations (partitioning + indexes)
cd backend
php artisan migrate --database=log_pgsql --path=database/migrations_log --force

# 2. Start API server, batch log worker, and React frontend
php artisan serve --host=127.0.0.1 --port=8000
php artisan logs:process-batches --batch=100
cd ../frontend/my-react-app && npm run dev

# 3. Simulate 4,000 logs & archive old logs to Parquet
php artisan logs:simulate --count=4000
php artisan logs:archive --days=90 --format=parquet
