API Logging Framework

In 30 seconds: Every API request is logged without making the user wait. Laravel sends the API response first, pushes the log into a local queue, inserts logs in batches of 100 into Neon PostgreSQL, reads logs from a Read Replica, and archives old months into compressed Parquet files.

1 How the Code Works (Step by Step)

STEP 1
User Sends Request
The React app (localhost:5173) sends API calls using Axios (src/api/axios.js) to Laravel (127.0.0.1:8000/api).
STEP 2
Middleware Starts Timer
ApiLoggerMiddleware::handle() records the start time and passes the request to the controller.
STEP 3
Customer Gets Instant Reply
The controller uses local PostgreSQL (pgsql) for users/notes and returns the HTTP response immediately.
STEP 4
Log Added to Queue
After the response is sent, terminate() pushes StoreApiLogJob into the local jobs table (api-logs queue).
STEP 5
Batch Insert into Neon
php artisan logs:process-batches reads 100 queued jobs at a time and saves them in 1 bulk INSERT to Neon Primary.
STEP 6
Logs Read from Replica
GET /api/logs (ApiLogController::index()) queries the Neon Read Replica so reads never slow down writes.

2 What Changed: Before vs. After

Area Before After (What We Built)
Database Setup Single local database Isolated Neon cloud DB (log_pgsql) for logs + local pgsql for app
Log Saving 1 SQL insert per request Queued (StoreApiLogJob) + 100-row bulk inserts (5,819 inserts/min)
Load Balancing & HA Single DB endpoint Neon multi-AZ HA + PgBouncer pooler + Read/Write replica splitting
Old Log Archival Slow row DELETE + large CSV files Monthly date partitions + compressed .parquet files (zstd)
Query Speed Full table scan (10.284 ms) BRIN + composite B-tree index (1.668 ms, 6.2x faster)

3 Completed Tasks & How Each Was Done

1. Dedicated PostgreSQL Server
DONE
Goal: Isolate heavy log writes from app tables.
How: Set up Neon (api-logs-db) in database.php & .env with SSL, and added $withinTransaction = false on log migrations for Neon's pooler.
Result: App data stays local; all API logs go to Neon.
2. Simulate 4,000+ Inserts/Min
DONE
Goal: Prove Neon + Laravel handle 4,000 logs/min without slowing responses.
How: Dispatched StoreApiLogJob to queue api-logs, built logs:process-batches & logs:simulate.
Result: Inserted 4,269 logs in 44.02s (5,819/min).
3. Load Balancing & HA
DONE
Goal: Keep DB highly available and split read/write load.
How: Enabled Neon multi-AZ storage + PgBouncer (-pooler) + Laravel read/write host split in database.php.
Result: Verified pg_is_in_recovery() = true on reads, false on writes.
4. Better Archival (Parquet)
DONE
Goal: Replace bloated CSV files & slow deletes.
How: Partitioned api_logs by month (2026_11, 2026_12, 2027_01, default) and updated logs:archive to export .parquet via export_to_parquet.py.
Result: Compressed archives + SHA-256 checksums tracked in api_log_archives.
5. Optimized Indexing
DONE
Goal: Speed up GET /api/logs without slowing inserts.
How: Added a tiny BRIN index on created_at + composite B-tree on (method, status_code, created_at DESC).
Result: EXPLAIN ANALYZE dropped from 10.284 ms → 1.668 ms.
6. Deployment & Ops Docs
DONE
Goal: Give the team clear setup, backup, and runbook docs.
How: Wrote docs/POSTGRESQL_OPERATIONS.md (runbook, SQL checks, pg_dump/pg_restore) and this visual guide.
Result: Ready for handoff & production operations.

5 Quick Commands

# 1. Run Neon log migrations (partitioning + indexes)
cd backend
php artisan migrate --database=log_pgsql --path=database/migrations_log --force

# 2. Start API server, batch log worker, and React frontend
php artisan serve --host=127.0.0.1 --port=8000
php artisan logs:process-batches --batch=100
cd ../frontend/my-react-app && npm run dev

# 3. Simulate 4,000 logs & archive old logs to Parquet
php artisan logs:simulate --count=4000
php artisan logs:archive --days=90 --format=parquet
